📋 API路径设计说明

🤖 VM自身操作接口 (v1路径)

这些接口由虚拟机自己调用，无需用户JWT认证：

  • POST /api/v1/vm/register - VM注册
  • POST /api/v1/vm/token/refresh - Token刷新
  • POST /api/v1/vm/{vmId}/heartbeat - 心跳上报
  • GET /api/v1/vm/health - 健康检查

👤 用户管理操作接口 (无v1路径)

这些接口由用户调用，需要用户JWT认证：

  • GET /api/vm/list - VM列表查询
  • GET /api/vm/{vmId} - VM详情查询
  • PUT /api/vm/{vmId} - VM信息更新
  • DELETE /api/vm/{vmId} - VM删除
  • POST /api/vm/{vmId}/start - VM启动
  • POST /api/vm/{vmId}/stop - VM停止
  • POST /api/vm/{vmId}/restart - VM重启
  • GET /api/vm/{vmId}/status - VM状态查询
💡 设计原理： VM自身操作使用 /api/v1/vm 路径，由VM拦截器处理；用户管理操作使用 /api/vm 路径，由用户JWT拦截器处理。 这样可以避免认证混乱，确保不同性质的操作使用正确的认证方式。

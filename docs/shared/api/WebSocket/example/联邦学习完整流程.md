# 联邦学习完整流程

本文档详细描述了基于WebSocket协议v1.4的联邦学习完整工作流程，严格遵循"后端控制一切，虚拟机只执行"的中心化架构设计。

## 1. 核心设计理念

### 1.1 架构原则
- **后端作为"大脑"**: 控制所有状态管理、决策逻辑、任务编排
- **虚拟机作为"手脚"**: 只响应后端指令，执行训练，上报结果
- **精确任务控制**: 通过taskId实现任务级别的精确控制
- **多任务支持**: 单台虚拟机可同时执行多个联邦学习任务

### 1.2 流程简化
移除了所有不必要的协商、通知和复杂状态管理，专注于核心的训练执行流程。

## 2. 联邦学习标准流程

### 2.1 虚拟机链路（被动响应模式）
```
1. 接收任务启动指令 (FEDERATED_TASK_START)
2. 确认任务接收 (FEDERATED_TASK_START_ACK)
3. 轮次循环执行:
   a) 接收轮次开始指令 (ROUND_START)
   b) 确认轮次开始 (ROUND_START_ACK)
   c) 执行本地训练 (本地处理，无消息交互)
   d) 训练完成，上传梯度 (GRADIENT_UPLOAD)
   e) 接收上传确认 (GRADIENT_UPLOAD_ACK)
   f) **进入等待状态** (被动等待后端聚合)
   g) 接收新全局模型 (GLOBAL_MODEL_BROADCAST)
   h) 确认模型接收 (GLOBAL_MODEL_BROADCAST_ACK)
   i) 接收轮次完成通知 (ROUND_COMPLETE)
   j) 确认轮次完成 (ROUND_COMPLETE_ACK)
4. 重复步骤3直到所有轮次完成
```

### 2.2 后端链路（完全控制模式）
```
1. 发起任务启动 (FEDERATED_TASK_START)
2. 等待所有虚拟机确认 (FEDERATED_TASK_START_ACK)
3. 轮次控制循环:
   a) 发起新轮次训练 (ROUND_START)
   b) 等待所有虚拟机确认 (ROUND_START_ACK)
   c) **监控训练进度** (通过心跳监控)
   d) 接收所有虚拟机梯度 (GRADIENT_UPLOAD)
   e) 确认梯度接收 (GRADIENT_UPLOAD_ACK)
   f) **执行模型聚合** (FedAvg/FedProx/FedNova/Scaffold)
   g) 广播新全局模型 (GLOBAL_MODEL_BROADCAST)
   h) 等待所有虚拟机确认 (GLOBAL_MODEL_BROADCAST_ACK)
   i) 发送轮次完成通知 (ROUND_COMPLETE)
   j) 等待所有虚拟机确认 (ROUND_COMPLETE_ACK)
4. 重复步骤3直到达到预设轮次或收敛条件
5. 生成最终模型，更新任务状态为COMPLETED
```

## 3. 详细流程步骤

### 3.1 任务启动阶段 (一次性)

#### 步骤1: 任务启动指令
```
后端 → 所有参与虚拟机: FEDERATED_TASK_START
```
**触发条件**: 管理员通过HTTP API创建并启动联邦学习任务

**消息内容**:
- taskId: 唯一任务标识，用于多任务并发控制
- federatedAlgorithm: 联邦算法类型 (FEDERATED_AVERAGING/FEDERATED_PROXIMAL/FEDERATED_NOVA/SCAFFOLD)
- totalRounds: 总训练轮次
- participants: 参与虚拟机列表
- initialGlobalModel: 初始全局模型参数
- localTrainingConfig: 本地训练配置
- **dataConfig**: 数据集配置，包含datasetId或dataPath

**后端职责**:
- 生成唯一的taskId确保任务隔离
- 选择合适的联邦算法和聚合策略
- 准备初始全局模型参数
- 确定参与的虚拟机列表和数据分发方案
- **精确控制**: 确保所有配置参数完整传递

#### 步骤2: 任务启动确认
```
每台虚拟机 → 后端: FEDERATED_TASK_START_ACK
```
**虚拟机职责**:
- 接收并解析任务配置，根据taskId创建任务上下文
- 根据dataConfig.datasetId或dataPath加载指定数据集
- 加载初始全局模型到本地训练器
- 初始化本地训练环境和算法参数
- 确认任务接收状态和就绪程度

**关键要求**:
- **多任务隔离**: 通过taskId确保与其他任务完全隔离
- **数据集验证**: 验证指定数据集是否可用
- **同步确认**: 所有参与虚拟机都必须发送确认，后端才进入轮次训练阶段

### 3.2 轮次训练阶段 (循环执行)

每个训练轮次严格按照以下步骤执行，直到完成所有预设轮次：

#### 步骤3: 轮次开始指令
```
后端 → 所有参与虚拟机: ROUND_START
```
**触发条件**:
- 第一轮: 所有虚拟机完成任务启动确认
- 后续轮: 所有虚拟机确认接收上一轮的全局模型

**消息内容**:
- taskId: 任务标识
- roundNumber: 当前轮次编号
- roundSpecificConfig: 轮次特定配置 (如学习率调整)
- expectedParticipants: 预期参与者数量

**后端职责**:
- 确保所有虚拟机就绪
- 同步启动新轮次
- 监控轮次执行状态

#### 步骤4: 轮次开始确认
```
每台虚拟机 → 后端: ROUND_START_ACK
```
**虚拟机职责**:
- 确认轮次配置
- 准备本地训练数据
- 预估训练时间

#### 步骤5: 本地训练执行
**虚拟机自主执行** (无WebSocket交互):
- 使用当前全局模型进行本地训练
- 计算模型参数的更新梯度
- 生成本地训练统计信息

**训练期间**: 虚拟机专注训练，后端通过心跳监控虚拟机状态

#### 步骤6: 梯度上传
```
每台虚拟机 → 后端: GRADIENT_UPLOAD
```
**触发条件**: 虚拟机完成本轮本地训练

**上传内容**:
- taskId: 任务标识
- roundNumber: 轮次编号
- gradientData: 计算的梯度信息
- trainingMetrics: 本地训练指标 (准确率、损失值、训练时间等)
- samplesCount: 参与训练的样本数量

**虚拟机职责**:
- 计算准确的梯度信息
- 压缩梯度数据以减少传输
- 提供完整的训练统计

#### 步骤7: 梯度上传确认
```
后端 → 每台虚拟机: GRADIENT_UPLOAD_ACK
```
**后端职责**:
- 验证梯度数据完整性
- 确认数据接收状态
- 通知虚拟机进入等待状态

#### 步骤8: 虚拟机等待状态 - **关键环节**
**虚拟机进入被动等待** (无WebSocket交互):
- 虚拟机完成梯度上传后**立即进入等待状态**
- **被动等待后端完成模型聚合**，不做任何主动操作
- 继续发送心跳维持连接，报告等待状态
- 此阶段虚拟机完全不知道聚合进度，体现被动响应特性

#### 步骤9: 模型聚合执行 - **后端独立处理**
**后端完全自主执行** (无WebSocket交互):
- **收集同步**: 必须收到该轮次所有参与虚拟机的梯度数据
- **聚合执行**: 根据任务配置的联邦算法执行聚合
  - FEDERATED_AVERAGING: 简单加权平均
  - FEDERATED_PROXIMAL: 带正则化项的聚合
  - FEDERATED_NOVA: 处理异构性的归一化聚合
  - SCAFFOLD: 控制变量方法聚合
- **模型生成**: 生成新的全局模型参数
- **指标计算**: 计算全局准确率、损失等性能指标

**控制要求**:
- 必须等待所有虚拟机完成该轮次才开始聚合
- 聚合过程中所有虚拟机保持等待状态

#### 步骤10: 全局模型广播 - **打破虚拟机等待状态**
```
后端 → 所有参与虚拟机: GLOBAL_MODEL_BROADCAST
```
**触发条件**: 后端完成模型聚合计算

**广播内容**:
- taskId: 任务标识
- roundNumber: 当前完成的轮次编号
- globalModel: 聚合后的全局模型参数
- aggregationInfo: 聚合统计信息 (全局准确率、损失值、参与者数量等)
- nextRoundConfig: 下一轮训练配置 (如学习率调整)

**后端职责**:
- **统一分发**: 必须同时向所有等待中的虚拟机广播新模型
- **数据完整性**: 确保模型参数传输无损
- **状态更新**: 将任务状态更新为"模型分发中"
- **同步控制**: 确保所有虚拟机同时接收到相同的全局模型

#### 步骤11: 全局模型接收确认 - **虚拟机恢复活跃**
```
每台虚拟机 → 后端: GLOBAL_MODEL_BROADCAST_ACK
```
**虚拟机职责**:
- **结束等待**: 从被动等待状态恢复到活跃状态
- **模型验证**: 验证接收到的全局模型参数完整性
- **模型更新**: 用新全局模型替换当前本地模型
- **环境准备**: 为下一轮训练准备计算环境和数据
- **状态确认**: 向后端确认已准备好进行下一轮训练

**关键要求**:
- 必须验证taskId和roundNumber的一致性
- 确保模型参数成功加载到本地训练器

#### 步骤12: 轮次完成通知 - **后端轮次封闭**
```
后端 → 所有参与虚拟机: ROUND_COMPLETE
```
**触发条件**: 所有虚拟机确认接收并更新全局模型

**通知内容**:
- taskId: 任务标识
- roundNumber: 刚完成的轮次编号
- roundResults: 完整轮次统计结果 (聚合准确率、训练时间、参与VM数量)
- taskProgress: 任务整体进度 (已完成轮次/总轮次)
- nextAction: 下一步动作 (继续下一轮或任务完成)

**后端职责**:
- **轮次封闭**: 正式宣告当前轮次完成，所有数据已同步
- **进度汇报**: 向所有虚拟机汇报整体任务进度
- **决策通知**: 告知虚拟机下一步行动 (继续训练或准备结束)

#### 步骤13: 轮次完成确认 - **虚拟机同步确认**
```
每台虚拟机 → 后端: ROUND_COMPLETE_ACK
```
**虚拟机职责**:
- **轮次确认**: 确认当前轮次已完全结束
- **状态同步**: 与后端保持轮次状态同步
- **准备就绪**: 表示已准备好接收下一轮指令

**同步要求**:
- 所有虚拟机必须发送确认后，后端才能启动下一轮
- 确保全局状态的严格一致性

**流程控制**:
- **继续训练**: 如果未达到总轮次数，后端返回步骤3发送下一个ROUND_START
- **任务完成**: 如果达到总轮次数，进入任务结束阶段

### 3.3 任务结束阶段 (一次性)

#### 任务完成条件
- 达到预设的总轮次数
- 模型收敛达到目标性能
- 管理员手动停止任务

#### 最终处理
**后端职责**:
- 保存最终全局模型到数据库
- 生成完整的训练报告
- 更新任务状态为COMPLETED
- 清理临时数据

**虚拟机职责**:
- 清理本地训练环境
- 释放任务相关资源
- 恢复空闲状态

## 4. 多任务并发支持 - **taskId精确控制**

### 4.1 任务隔离机制
- **消息标识**: 每个WebSocket协议消息都包含唯一taskId字段
- **资源隔离**: 虚拟机根据taskId完全隔离不同任务的计算资源、数据、模型
- **独立控制**: 后端可以对每个taskId独立发送控制指令，不影响其他任务
- **状态隔离**: 每个taskId维护独立的轮次状态、训练进度、模型版本

### 4.2 精确控制能力
**后端可以精确控制每个联邦学习任务**:
- 对不同taskId发送不同的协议消息类型
- 控制每个任务的轮次进度（任务A进入轮次5，任务B进入轮次2）
- 独立管理每个任务的参与虚拟机列表
- 分别配置每个任务的联邦算法和训练参数

**后端可以精确控制每个虚拟机中的每个任务**:
- 向VM-001发送taskA的ROUND_START，同时向VM-001发送taskB的GLOBAL_MODEL_BROADCAST
- 不同任务可以处于完全不同的执行阶段
- 每个任务独立响应，互不干扰

### 4.3 并发场景示例
```
VM-001 同时执行多任务:
├── taskA (轮次3/10, 状态: 本地训练中)
├── taskB (轮次1/8, 状态: 等待新全局模型)
└── taskC (轮次7/12, 状态: 上传梯度完成)

VM-002 同时执行多任务:
├── taskA (轮次3/10, 状态: 梯度上传完成)
├── taskB (轮次1/8, 状态: 接收任务启动)
└── taskD (轮次2/5, 状态: 轮次完成确认)
```

**后端精确控制示例**:
```
同时发送不同指令到相同虚拟机:
- VM-001: GRADIENT_UPLOAD_ACK (taskA) + GLOBAL_MODEL_BROADCAST (taskB) + ROUND_COMPLETE (taskC)
- VM-002: ROUND_START (taskA) + FEDERATED_TASK_START_ACK (taskB) + ROUND_START (taskD)
```

**虚拟机并发处理**:
- 根据taskId路由到不同的任务处理器
- 每个任务独立维护训练状态和模型参数
- 并发执行多个任务的训练、上传、等待操作
- 资源调度和优先级由虚拟机本地管理

## 5. 关键设计特点 - **v1.4协议简化**

### 5.1 极简化的消息流程
**移除的冗余协议 (v1.3 → v1.4)**:
- ❌ MODEL_TYPE_NEGOTIATION: 移除模型类型协商，后端直接指定
- ❌ ALGORITHM_CONFIG: 移除算法配置协商，在任务启动时直接配置
- ❌ TRAINING_START_COMMAND: 移除独立训练指令，合并到ROUND_START
- ❌ AGGREGATION_START/COMPLETE: 移除聚合通知，后端内部处理
- ❌ PARTICIPANT_LIST_UPDATE: 移除参与者列表更新，任务启动时确定
- ❌ MODEL_VALIDATION_REQUEST/RESPONSE: 移除模型验证协商
- ❌ TRAINING_STATUS_QUERY: 移除训练状态查询，通过心跳获取

**保留的核心协议 (34个消息)**:
- ✅ 任务生命周期: START/STOP/RESUME/DELETE
- ✅ 轮次控制: ROUND_START/COMPLETE
- ✅ 数据传输: GRADIENT_UPLOAD/GLOBAL_MODEL_BROADCAST
- ✅ 确认机制: 所有ACK消息
- ✅ 错误处理: ERROR消息
- ✅ 连接管理: CONNECT/DISCONNECT/HEARTBEAT

### 5.2 中心化状态管理
**后端完全控制**:
- 所有任务状态 (PENDING/RUNNING/PAUSED/COMPLETED/FAILED)
- 所有轮次进度 (当前轮次/总轮次/参与者状态)
- 所有虚拟机状态 (在线/离线/训练中/等待中)
- 所有模型版本 (全局模型/局部梯度/聚合历史)

**虚拟机无状态化**:
- 不维护全局任务状态，只知道当前接收到的指令
- 不需要复杂的状态机，只需响应后端指令
- 通过taskId识别任务，通过心跳报告自身状态
- 专注执行: 训练→上传→等待→接收→重复

### 5.3 简化错误处理机制
**虚拟机错误报告**:
- 只需发送ERROR消息给后端，包含错误类型和描述
- 不需要自主决策错误恢复策略
- 所有异常情况都上报给后端统一处理

**后端错误决策**:
- 集中式错误分析和恢复策略决策
- 可以选择重试、跳过、暂停或终止任务
- 统一的错误日志和异常追踪
- 支持任务级和虚拟机级的错误隔离

**网络恢复**:
- 心跳机制检测网络中断
- 自动重连后继续当前任务状态
- 支持任务暂停和恢复机制

## 6. 性能和可靠性保证

### 6.1 严格同步控制
**轮次级同步**:
- 每个轮次都有明确的同步点: 开始→训练→上传→聚合→分发→完成
- 后端等待所有虚拟机完成当前阶段才进入下一阶段
- 通过ACK确认机制确保每个虚拟机都与后端状态同步

**任务级同步**:
- 任务启动时必须所有参与虚拟机都确认接收
- 轮次完成时必须所有虚拟机都确认接收新模型
- 支持超时机制和部分虚拟机失败的降级处理

**多任务同步**:
- 不同taskId的任务独立同步，互不影响
- 每个任务维护独立的同步状态和进度

### 6.2 数据完整性保障
**模型数据校验**:
- 所有全局模型和梯度数据包含MD5或SHA256校验信息
- 虚拟机接收数据后必须验证完整性
- 传输错误时自动重试，超过阈值则报告错误

**数据压缩优化**:
- 支持梯度数据压缩减少网络传输量
- 模型参数差量传输 (只传输变化部分)
- 可配置的压缩级别平衡性能和网络使用

**版本一致性**:
- 每个模型版本都有唯一标识符
- 确保所有虚拟机使用相同版本的全局模型进行训练
- 支持模型版本回滚和恢复

### 6.3 扩展性和性能
**虚拟机规模**:
- 优化支持1-10台虚拟机的高效协调
- 局域网环境下的低延迟通信 (<100ms)
- 支持异构虚拟机配置 (不同计算能力、网络带宽)

**架构简化优势**:
- 中心化架构减少虚拟机间通信复杂度
- 简化的协议便于维护、调试和故障排查
- 后端统一监控所有虚拟机状态和性能指标

**性能监控**:
- 实时监控每个虚拟机的训练进度和网络状态
- 收集详细的性能指标: 训练时间、网络延迟、数据传输量
- 支持性能瓶颈分析和优化建议

这个流程确保了联邦学习在中心化架构下的高效执行，后端完全控制整个训练过程，虚拟机专注于执行训练任务。

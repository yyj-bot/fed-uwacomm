# 联邦学习完整流程

本文档详细描述了基于WebSocket协议v1.4的联邦学习完整工作流程，严格遵循"后端控制一切，虚拟机只执行"的中心化架构设计。

## 1. 核心设计理念

### 1.1 架构原则
- **后端作为"大脑"**: 控制所有状态管理、决策逻辑、任务编排
- **虚拟机作为"手脚"**: 只响应后端指令，执行训练，上报结果
- **精确任务控制**: 通过taskId实现任务级别的精确控制
- **多任务支持**: 单台虚拟机可同时执行多个联邦学习任务

### 1.2 流程简化
移除了所有不必要的协商、通知和复杂状态管理，专注于核心的训练执行流程。

## 2. 联邦学习标准流程

### 2.1 虚拟机链路
```
接收任务启动指令 → 开始第一轮训练 → 训练完成上传梯度 →
进入等待状态 → 接收新全局模型 → 使用新模型进行下一轮训练 →
重复直到所有轮次完成
```

### 2.2 后端链路
```
发起任务启动 → 发起第一轮训练 → 接收所有虚拟机梯度 →
执行模型聚合 → 广播新全局模型 → 发起下一轮训练 →
重复直到所有轮次完成 → 生成最终模型
```

## 3. 详细流程步骤

### 3.1 任务启动阶段 (一次性)

#### 步骤1: 任务启动指令
```
后端 → 所有参与虚拟机: FEDERATED_TASK_START
```
**触发条件**: 管理员通过HTTP API创建联邦学习任务

**消息内容**:
- taskId: 唯一任务标识
- federatedAlgorithm: 联邦算法类型 (FEDERATED_AVERAGING/FEDERATED_PROXIMAL/FEDERATED_NOVA/SCAFFOLD)
- totalRounds: 总训练轮次
- participants: 参与虚拟机列表
- initialGlobalModel: 初始全局模型参数
- localTrainingConfig: 本地训练配置

**后端职责**:
- 生成唯一的taskId
- 选择合适的联邦算法
- 准备初始全局模型
- 确定参与的虚拟机列表

#### 步骤2: 任务启动确认
```
每台虚拟机 → 后端: FEDERATED_TASK_START_ACK
```
**虚拟机职责**:
- 接收并解析任务配置
- 加载初始全局模型
- 准备本地训练环境
- 确认任务接收状态

**确认条件**: 所有参与虚拟机都必须发送确认，后端才进入下一阶段

### 3.2 轮次训练阶段 (循环执行)

每个训练轮次严格按照以下步骤执行，直到完成所有预设轮次：

#### 步骤3: 轮次开始指令
```
后端 → 所有参与虚拟机: ROUND_START
```
**触发条件**:
- 第一轮: 所有虚拟机完成任务启动确认
- 后续轮: 所有虚拟机确认接收上一轮的全局模型

**消息内容**:
- taskId: 任务标识
- roundNumber: 当前轮次编号
- roundSpecificConfig: 轮次特定配置 (如学习率调整)
- expectedParticipants: 预期参与者数量

**后端职责**:
- 确保所有虚拟机就绪
- 同步启动新轮次
- 监控轮次执行状态

#### 步骤4: 轮次开始确认
```
每台虚拟机 → 后端: ROUND_START_ACK
```
**虚拟机职责**:
- 确认轮次配置
- 准备本地训练数据
- 预估训练时间

#### 步骤5: 本地训练执行
**虚拟机自主执行** (无WebSocket交互):
- 使用当前全局模型进行本地训练
- 计算模型参数的更新梯度
- 生成本地训练统计信息

**训练期间**: 虚拟机专注训练，后端通过心跳监控虚拟机状态

#### 步骤6: 梯度上传
```
每台虚拟机 → 后端: GRADIENT_UPLOAD
```
**触发条件**: 虚拟机完成本轮本地训练

**上传内容**:
- taskId: 任务标识
- roundNumber: 轮次编号
- gradientData: 计算的梯度信息
- trainingMetrics: 本地训练指标 (准确率、损失值、训练时间等)
- samplesCount: 参与训练的样本数量

**虚拟机职责**:
- 计算准确的梯度信息
- 压缩梯度数据以减少传输
- 提供完整的训练统计

#### 步骤7: 梯度上传确认
```
后端 → 每台虚拟机: GRADIENT_UPLOAD_ACK
```
**后端职责**:
- 验证梯度数据完整性
- 确认数据接收状态
- 通知虚拟机进入等待状态

#### 步骤8: 虚拟机等待状态
**虚拟机进入等待** (无WebSocket交互):
- 虚拟机完成梯度上传后自动进入等待状态
- 等待后端完成模型聚合
- 继续发送心跳维持连接

#### 步骤9: 模型聚合执行
**后端自主执行** (无WebSocket交互):
- 收集所有虚拟机的梯度信息
- 执行联邦聚合算法 (FedAvg/FedProx/FedNova/SCAFFOLD)
- 生成新的全局模型参数
- 计算全局性能指标

**聚合条件**: 必须收到所有参与虚拟机的梯度数据

#### 步骤10: 全局模型广播
```
后端 → 所有参与虚拟机: GLOBAL_MODEL_BROADCAST
```
**触发条件**: 后端完成模型聚合

**广播内容**:
- taskId: 任务标识
- roundNumber: 新轮次编号
- globalModel: 聚合后的全局模型参数
- aggregationInfo: 聚合统计信息 (全局准确率、损失值、参与者数量等)
- nextRoundConfig: 下一轮训练配置

**后端职责**:
- 确保模型数据完整性
- 同步分发给所有虚拟机
- 更新任务状态

#### 步骤11: 全局模型接收确认
```
每台虚拟机 → 后端: GLOBAL_MODEL_BROADCAST_ACK
```
**虚拟机职责**:
- 接收并验证全局模型
- 更新本地模型参数
- 准备下一轮训练

#### 步骤12: 轮次完成通知
```
后端 → 所有参与虚拟机: ROUND_COMPLETE
```
**触发条件**: 所有虚拟机确认接收新全局模型

**通知内容**:
- taskId: 任务标识
- roundNumber: 完成的轮次编号
- roundResults: 轮次统计结果
- nextRound: 下一轮信息或任务完成通知

#### 步骤13: 轮次完成确认
```
每台虚拟机 → 后端: ROUND_COMPLETE_ACK
```

**流程重复**: 如果未达到总轮次数，返回步骤3开始下一轮

### 3.3 任务结束阶段 (一次性)

#### 任务完成条件
- 达到预设的总轮次数
- 模型收敛达到目标性能
- 管理员手动停止任务

#### 最终处理
**后端职责**:
- 保存最终全局模型到数据库
- 生成完整的训练报告
- 更新任务状态为COMPLETED
- 清理临时数据

**虚拟机职责**:
- 清理本地训练环境
- 释放任务相关资源
- 恢复空闲状态

## 4. 多任务并发支持

### 4.1 任务隔离
- 每个WebSocket消息都包含taskId字段
- 虚拟机根据taskId隔离不同任务的资源
- 后端可以独立控制每个任务的执行

### 4.2 并发场景示例
```
VM-001 同时执行:
├── taskA (轮次3/10, 状态: 训练中)
└── taskB (轮次1/8, 状态: 等待新模型)
```

**后端控制**:
- 可以对taskA发送ROUND_START，对taskB发送GLOBAL_MODEL_BROADCAST
- 虚拟机根据taskId分别处理不同任务的消息
- 资源分配和调度由虚拟机本地管理

## 5. 关键设计特点

### 5.1 简化的消息流
- 移除了MODEL_TYPE_NEGOTIATION (协商消息)
- 移除了ALGORITHM_CONFIG (配置消息)
- 移除了TRAINING_START_COMMAND (训练指令)
- 移除了AGGREGATION_START/COMPLETE (聚合通知)
- 专注核心训练流程

### 5.2 状态管理简化
- 后端维护所有任务和轮次状态
- 虚拟机不需要复杂的状态转换逻辑
- 通过心跳简单判断虚拟机在线状态

### 5.3 错误处理简化
- 虚拟机只需要通过ERROR消息报告异常
- 所有错误恢复策略由后端决策
- 网络中断通过心跳机制检测

## 6. 性能和可靠性

### 6.1 同步控制
- 每个阶段都有明确的同步点
- 后端确保所有虚拟机步调一致
- 支持部分虚拟机失败的降级处理

### 6.2 数据完整性
- 所有模型和梯度数据都包含校验信息
- 传输错误自动重试
- 支持压缩减少网络传输

### 6.3 扩展性
- 支持10台以内虚拟机的高效协调
- 局域网环境下的低延迟通信
- 简化架构便于维护和调试

这个流程确保了联邦学习在中心化架构下的高效执行，后端完全控制整个训练过程，虚拟机专注于执行训练任务。

# WebSocket 协议废弃接口 - v1.5 移除说明

## 概述

本文档描述了从WebSocket协议v1.4到v1.5版本升级过程中移除的接口和功能。v1.5版本在数据集管理方面引入了**破坏性变更**，完全移除对v1.4数据集ID体系的兼容性，转向统一的assignedDatasetId管理架构。

⚠️ **重要警告**: v1.5版本在数据集管理方面不兼容v1.4，需要完全重写相关逻辑。

## 重大变更概述

### 协议数量变化
- **新增协议数量**: 2个新协议消息
- **概念性移除**: v1.4的datasetId体系被完全废弃
- **协议总数**: 34个 → 36个协议
- **核心目标**: 通过破坏性变更实现统一的数据集ID管理架构

### 设计理念变更
- **保持简洁**: 继承v1.4的简化设计理念，避免过度复杂化
- **功能增强**: 专注于数据集关联管理和13步标准化流程
- **⚠️ 破坏性升级**: 数据集管理完全不兼容v1.4，需要重写实现
- **统一架构**: 继续支持taskId多任务并发和中心化控制

## 1. v1.5版本移除内容分析

### 1.1 协议消息移除情况

**✅ 无协议消息被移除**

v1.5版本采用了**渐进式增强**的设计策略，所有v1.4的34个核心协议消息均得到保留：

```
保留的核心协议组 (34个，完全兼容):
✅ 任务管理协议 (8个): FEDERATED_TASK_* 系列
✅ 轮次控制协议 (8个): ROUND_* 系列
✅ 模型传输协议 (6个): GRADIENT_UPLOAD, GLOBAL_MODEL_BROADCAST 系列
✅ 状态监控协议 (6个): VM_STATUS_*, FEDERATED_TASK_STATUS_* 系列
✅ 连接管理协议 (4个): CONNECT, DISCONNECT, HEARTBEAT 系列
✅ 系统控制协议 (2个): SYSTEM_STATUS_*, ERROR_* 系列
```

### 1.2 设计模式移除情况

**✅ 无设计模式被移除**

v1.5版本继续坚持v1.4确立的简化设计模式：
- 保持精简的请求-响应ACK机制
- 继续使用统一的双层状态监控
- 维持中心化的任务配置下发模式

## 2. v1.5版本功能废弃分析

### 2.1 实际废弃功能

由于v1.5版本是纯增量升级，**没有任何功能被实际废弃**。所有v1.4功能均继续支持。

### 2.2 概念性废弃内容

#### 2.2.1 10步联邦学习流程 (概念废弃)

**废弃原因**: 升级为更完整的13步标准化流程

```
❌ 概念废弃: v1.4的10步简化流程
1. 任务启动
2. 轮次开始
3. 本地训练
4. 梯度上传
5. 模型聚合
6. 全局模型广播
7. 轮次完成
8. 重复轮次循环
9. 任务完成
10. 资源清理

✅ 升级为: v1.5的13步完整流程
1. 任务启动确认
2. 数据集预查询 (🆕)
3. 数据集分发
4. 数据集创建确认 (🆕)
5. 轮次开始
6. 本地训练执行
7. 梯度上传
8. 梯度聚合
9. 全局模型广播
10. 模型更新确认
11. 轮次完成
12. 重复轮次循环
13. 任务完成
```

**技术影响**: 这是概念性升级，不影响现有协议消息的使用

#### 2.2.2 简单数据集指定方式 (概念废弃)

**废弃原因**: 升级为统一的后端ID分配机制

```
❌ 概念废弃: v1.4的简单数据集指定
{
  "type": "FEDERATED_TASK_START",
  "data": {
    "dataConfig": {
      "datasetId": "用户指定ID",          // 简单指定
      "dataPath": "/data/training"      // 本地路径
    }
  }
}

✅ 升级为: v1.5的统一ID管理（破坏性变更）
{
  "type": "FEDERATED_TASK_START",
  "data": {
    "dataConfig": {
      "assignedDatasetId": "backend-generated-uuid",  // 🆕 v1.5：唯一数据集标识符
      "dataPath": "/data/training"
    }
  }
}
```

**技术影响**: ⚠️ 破坏性变更 - v1.4的datasetId完全移除，必须使用assignedDatasetId

## 3. 数据集管理破坏性变更

```
兼容性矩阵:

❌ v1.5 数据集逻辑 ↔ v1.4 服务端: 完全不兼容
✅ v1.5 非数据集功能 ↔ v1.4 服务端: 基本兼容
```

## 5. v1.5新增协议说明

### 5.1 新增协议列表

v1.5版本新增了2个协议消息：

#### DATASET_LIST_QUERY 🔵 (新增)
```json
{
  "type": "DATASET_LIST_QUERY",
  "id": "query-uuid-generated",
  "vmId": "vm-001",
  "data": {
    "taskId": "fedtask-123456",
    "queryType": "ASSIGNED_DATASETS"
  }
}
```

#### DATASET_LIST_RESPONSE 🔵 (新增)
```json
{
  "type": "DATASET_LIST_RESPONSE",
  "id": "response-uuid-generated",
  "data": {
    "taskId": "fedtask-123456",
    "datasets": [
      {
        "assignedDatasetId": "dataset-uuid-backend",
        "status": "CREATED",
        "createdAt": "2025-01-28T10:30:00.000Z",
        "localPath": "/data/assigned/dataset-uuid-backend"
      }
    ],
    "totalCount": 1
  }
}
```

### 5.2 新增字段说明

#### FEDERATED_TASK_START增强
```json
{
  "type": "FEDERATED_TASK_START",
  "data": {
    "assignedDatasetId": "dataset-uuid-generated-by-backend", // 🆕 v1.5新增
    "dataConfig": {
      // 现有字段保持不变
    }
  }
}
```

## 6. 数据库架构更新

### 6.1 新增字段 (向后兼容)

```sql
-- v1.5新增字段，全部为可选字段，不影响现有数据
ALTER TABLE task_participants ADD COLUMN assigned_dataset_id VARCHAR(32) NULL
  COMMENT 'v1.5后端分配的数据集ID(32位UUID)';

ALTER TABLE task_participants ADD COLUMN dataset_status
  ENUM('PENDING', 'CREATED', 'UPLOADING', 'COMPLETED', 'FAILED')
  DEFAULT 'PENDING' COMMENT 'v1.5数据集状态';

ALTER TABLE task_participants ADD COLUMN dataset_created_at TIMESTAMP NULL
  COMMENT 'v1.5数据集创建时间';

ALTER TABLE task_participants ADD COLUMN dataset_completed_at TIMESTAMP NULL
  COMMENT 'v1.5数据集完成时间';
```

### 6.2 索引优化
```sql
-- v1.5新增索引，提升数据集查询性能
CREATE INDEX idx_assigned_dataset_id ON task_participants(assigned_dataset_id);
CREATE INDEX idx_dataset_status ON task_participants(dataset_status);
```

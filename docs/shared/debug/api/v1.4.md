# API v1.4 Bug 反馈

## 后端问题

### 1. 联邦学习任务列表查询接口数据库字段缺失

**涉及接口文档**: `federated-task-api-reference.md`  
**具体接口**: `3.9 任务列表查询接口` - `GET /api/federated/tasks`  

**问题描述**:
- **接口文档期望**: 前端传递查询参数 `page`, `size`, `status`, `type`, `startDate`, `endDate`, `keyword`
- **后端实际行为**: SQL查询中使用了 `created_by` 字段进行过滤
- **与接口文档不符**: 后端自动添加了文档中未定义的 `created_by` 过滤条件

**错误信息**:
```
java.sql.SQLSyntaxErrorException: Unknown column 'created_by' in 'where clause'
SQL: SELECT * FROM federated_tasks WHERE created_by = ? ORDER BY created_at DESC LIMIT ?
```

**问题根源**:
- **文件**: `FederatedTasksMapper.xml` 第160-162行
- **问题**: 后端代码逻辑正确，但数据库表 `federated_tasks` 中缺少 `created_by` 字段
- **前端检查**: ✅ 前端严格按照接口文档开发，未传递 `createdBy` 参数

### 2. 虚拟机列表查询接口返回数据格式不符合文档规范

**涉及接口文档**: `vm-api-reference.md`  
**具体接口**: `4.1 虚拟机列表查询接口` - `GET /api/vm/list`  

**问题描述**:
- **接口文档期望格式**:
  ```json
  {
    "data": {
      "total": 10,
      "page": 1,
      "size": 20,
      "pages": 1,
      "list": [...]
    }
  }
  ```

- **后端实际返回格式**:
  ```json
  {
    "total": 0,
    "pages": 0,
    "current": 1,      // ❌ 应该是 "page"
    "size": 100,
    "records": []      // ❌ 应该是 "list"
  }
  ```

- **与接口文档不符**: 后端使用 `current` 和 `records` 字段，而文档规定使用 `page` 和 `list` 字段

**问题根源**:
- **控制器**: `VmManagementController.java` 第87行返回 `PageResult<VmListVO>`
- **分页类**: `PageResult.java` 定义了字段 `current`, `records`
- **前端检查**: ✅ 前端严格按照接口文档开发，期望 `page` 和 `list` 字段

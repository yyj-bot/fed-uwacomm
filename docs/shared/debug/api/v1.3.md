## 📋 Bug 修复清单

### 🚨 高优先级 Bug

#### BUG-001: 任务列表查询接口 SQL 语法错误

**问题描述：**
- 任务列表查询接口返回数据库 SQL 语法错误
- 错误信息：`Unknown column 'created_by' in 'where clause'`

**影响范围：**
- **接口文档：** `federated-task-api-reference.md`
- **具体接口：** 第3.9节 - 任务列表查询接口 (`GET /api/federated/tasks`)
- **前端调用：** 任务列表页面无法正常加载

**技术详情：**
- **后端文件：** `backend-springboot/feduwacomm-server/src/main/resources/mapper/FederatedTasksMapper.xml`
- **问题方法：** `selectTasksByQuery` (第161-163行)
- **问题代码：**
  ```xml
  <if test="createdBy != null and createdBy != ''">
      AND created_by = #{createdBy}
  </if>
  ```

**根本原因：**
1. 数据库表 `federated_tasks` 中没有 `created_by` 字段
2. API 文档中的查询参数也没有定义 `createdBy` 参数
3. 但后端 Mapper 中包含了对该字段的查询条件

**修复方案：** 需要后端开发人员修复

**错误日志：**
```
### Error querying database.  Cause: java.sql.SQLSyntaxErrorException: Unknown column 'created_by' in 'where clause'
### The error may exist in file [D:\Projects\fed-uwacomm\backend-springboot\feduwacomm-server\target\classes\mapper\FederatedTasksMapper.xml]
### The error may involve com.feduwacomm.mapper.FederatedTasksMapper.selectTasksByQuery-Inline
### SQL: SELECT * FROM federated_tasks WHERE created_by = ? ORDER BY created_at DESC LIMIT ?
```

**状态：** 🔴 待修复

### 🔧 中优先级 Bug

#### BUG-002: 后端未实现v1.3接口兼容性承诺

**问题描述：**
- 接口文档明确规定：`v1.3 版本同时支持新旧两种参数格式`
- 后端验证逻辑只检查旧格式 `participants` 字段
- 后端未实现对新格式 `participantConfig.participants` 的支持
- 导致"参与者列表不能为空"验证失败

**影响范围：**
- **接口文档：** `federated-task-api-reference.md`
- **具体接口：** 任务创建接口 (`POST /api/federated/tasks`)
- **前端调用：** 任务创建功能完全不可用

**技术详情：**
- **后端文件：** `backend-springboot/feduwacomm-server/src/main/java/.../FederatedTaskService.java`
- **问题方法：** `validateCreateTaskRequest` (第571行)
- **问题代码：**
  ```java
  if (!data.participants || !Array.isArray(data.participants) || data.participants.length === 0) {
      throw new Error('参与者列表不能为空')
  }
  ```

**根本原因：**
1. **接口规范要求**：`modified-interfaces-v1.3.md` 要求向后兼容性
2. **后端未实现**：只支持旧格式验证，违背接口文档承诺

**修复方案：** 需要后端开发人员修复

**状态：** 🔴 待修复

### ⚠️ 低优先级 Bug

#### BUG-003: VM列表接口返回数据格式不符合API文档规范

**问题描述：**
- VM列表接口返回的数据字段名与API文档不一致
- 后端返回 `current` 和 `records`，文档规定应为 `page` 和 `list`
- 导致前端无法正确解析数据

**影响范围：**
- **接口文档：** `vm-api-reference.md`
- **具体接口：** 第4.1节 - VM列表查询接口 (`GET /api/vm/list`)
- **前端调用：** TaskCreatePage VM选择功能无法正常工作

**技术详情：**
- **后端文件：** VmInstancesController 相关实现
- **问题字段：** `current` 应为 `page`，`records` 应为 `list`
- **实际返回：** `{"total":0,"pages":0,"current":1,"size":100,"records":[]}`
- **文档规范：** `{"total":0,"pages":0,"page":1,"size":100,"list":[]}`

**根本原因：**
1. **后端实现不规范**：未按API文档标准实现分页响应格式
2. **字段命名不一致**：使用了非标准的字段名
3. **缺乏接口规范检查**：后端开发时未对照API文档验证

**修复方案：** 需要后端开发人员修复

**状态：** 🔴 待修复

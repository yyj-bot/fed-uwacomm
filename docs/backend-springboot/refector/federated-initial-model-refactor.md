# 联邦学习初始模型/数据集解耦后端重构计划（v1.5）

## 1. 背景与目标
- 文档更新要求初始模型在任务创建前完成生成/上传，`initialModelConfig` 成为任务创建与配置接口的唯一入口。
- 后端需要移除初始模型接口对 `taskId` 的依赖，引入模型绑定状态管理，并支持 `AUTO` / `CUSTOM` 双模式。
- 所有改动必须严格遵循团队“打卡机制”：每个任务节点在开始、暂停、完成时记录时间、执行人和摘要，确保可追溯。

## 2. 打卡机制要求
- 每个任务项在每日 standup 前后至少各一次打卡，记录内容包含：日期、进度百分比、阻塞点。
- 任何跨文件的接口签名修改必须同步更新打卡备注，说明涉及文件范围与影响模块。
- 未打卡的任务视为未启动，不得进入下一阶段。

## 4. 风险与依赖
- **Schema/数据库变更**：若现有表未保存模型绑定信息，需新增字段（例如 `initial_models.task_id` 等），应提前评估迁移脚本。
- **前端兼容性**：接口输出结构变更需同步前端，建议在控制器任务完成时更新打卡备注并通知前端负责人。
- **自动生成策略**：需确认业务是否已有默认架构模板，避免 `AUTO` 模式缺省导致运行时异常。

## 7. 下一步计划
1. 梳理任务创建 → 自动资源准备链路：在 `createTask` 完成后统一触发分发，修正 `buildConfigSummaryFromTask` / `extractInitialModelSummary` 读取逻辑，确保初始模型绑定信息同步到 VO。
2. 完善 `prepareTaskResources`：将数据集、初始模型分发调用落到新的内部服务，处理 ACK 等待、错误回滚，并记得收集分发结果用于任务状态判断。
3. 修复工作流阶段处理器抽象层：为 `AbstractStageHandler`、`StageHandler` 建立单一权威定义，删除旧模块内冲突版本，避免 `ClassFormatError`；同时梳理 DataDistribution/ModelDistribution/FederatedTraining handler 的行为，使其兼容新的 READY 流程。
4. 捕获全局模型迭代：在聚合完成后写入 `global_models`，并驱动 `GLOBAL_MODEL_BROADCAST` → `MODEL_RECEIVE_ACK`，Mock VM 缓存历史版本以便 E2E 检查。
5. 更新 E2E 测试与文档：`CompleteFederatedLearningFlowTestV151` 对 READY 状态、分发完成、全局模型历史添加断言，流程图与开发文档同步描述新链路。
